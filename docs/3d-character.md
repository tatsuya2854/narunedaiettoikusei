### 動き（7つ・すべて手元で作成）

Tripo のプリセット（人間のモーションキャプチャ）は、三頭身に当てると **体がゆらゆら・頭がふらふら・手首が丸まる**（フニャフニャ）うえ、
`animate_in_place` を指定しても walk が前に進んでしまった。なので **Tripo には骨（リグ）だけ入れてもらい、動きは全部手元で作る**（`generation.motion: "procedural"`）。

目標は「どうぶつの森」：小さくキビキビ・一歩ごとにポンと弾む・頭はぶれない・手は開いたまま。

| 状態 | 動き |
|---|---|
| IDLE | ほんの少し上下に息をして、体が左右にゆっくり揺れる |
| WALK | 小さい歩幅でテンポよく（0.56秒で2歩）。一歩ごとに弾み、腕は小さく前後 |
| JUMP | しゃがむ → ピョン（腕を上げる）→ 着地で少し沈む（1回きり） |
| HAPPY | 腕を斜め上・少し前に上げて、ぴょんぴょん（真上は頭にめり込むので避けた） |
| DANCE | 拍に合わせて左右にステップ、腕を交互に上げ、ひざでリズム |
| SLEEP | 立ったままうとうと。頭がこくりと前に傾き、腕はだらん |
| EAT | 右手を口元へ運んでもぐもぐ×2（腕は「向ける方向」で指定＝簡易IK） |

- レシピは `tools/character/lib/procedural-clips.mjs`。回転は「体の前・上・右」の軸で書き、骨ごとのローカル軸に変換する
- 手首（Hand）とねじれ骨は触らない → 手の形がくずれない。前に進む移動は入れない（その場で動く）
- 確認は `node tools/character/render-views.mjs <glb> out.png --clip=eat --dir=0,0,1 --times=0,0.2,0.4` で正面・横から必ず見る
- モデルは 245KB（Tripo のアニメ入りは 789KB だった）

### 体を「どうぶつの森」風に作り直した（2026-09-29）

Tripo のメッシュ（AIの形）は表面がデコボコで、顔の比率も崩れ、「不細工」と言われた。
なので **体は Tripo を使わず、元絵の比率どおりになめらかな単純形から手元で作る**（`npm run character -- toon naru`、`tools/character/lib/toon-model.mjs`）。

- 丸く大きな頭（顔の前は少し平ら）・耳付き帽子（顔のまわりはなめらかにくぼませて縁を作る）・帽子の点3つ・右上へ張り出す葉っぱ形のポニーテール
- ずんどうのTシャツ・短パン・短く太い脚・丸い靴・短い腕と丸い手
- **トゥーン（アニメ調）の陰影**（明・中・影の3段）。テクスチャなし・材質ごとに1メッシュ（8メッシュ）・153KB
- 顔は描かない → 2Dと同じ顔パーツを顔シートに描く（目は開けない）。服の色替えは材質の色を変えるだけ
- Tripo で作ったモデルは `models/` と `animations/` に残してある（元に戻すなら `character.json` の model を差し替え）

### 表情・着せ替え・アクセ（3D）

- **表情**：Tripo のモデルには顔が焼き込まれていて（色だけでなく浮き彫りの形も）動かせない。最適化のときに
  1. テクスチャの顔パーツを見つけ、元絵の顔パーツの位置と合わせる（キャリブレーション）
  2. 顔の凹凸を、まわりに当てはめた楕円体の面へならす
  3. 焼き込みの顔を肌色で塗る
  4. 頭の前面に沿う薄い「顔シート」を頭の骨に付ける
  → ゲームは顔シートに、**2Dと同じ顔パーツを2Dと同じ表情の数値（EXPR）で**描く。口パク・細め目・しょんぼり・どや・おどろき…が3Dでも同じに動く。**目は開けない**（閉じ目のパーツしか無い）
- **着せ替え**：2D と同じく、シャツ（黄）と短パン（グレー）の画素だけ色を変える。モデルは作り直さない
- **アクセ**：どうぶつの森風に、丸い基本形（球・ドーナツ・円柱・円すい）でその場で作って頭の骨に付ける（`3d/accessories.js`）。ハチマキは頭の断面の形に沿わせ、サングラスは目の位置の顔の丸みに沿わせる
- 確認：`node tools/character/look-shots.mjs out.png face base squint wow` / `wear mint:ribbon` / `side cheer:shades:60`

### 実際にやってわかったこと

- **Tripo API v2 は 2026-11-01 に停止**（コンソールの告知）。v3（`openapi.tripo3d.ai/v3`）に移行済み。`--provider tripo` は v3
- **出力は +X が正面**（`export_orientation` 既定）。最適化で -90° 回して +Z 正面に焼き込む
- **retarget に animations を複数入れても、GLB には最後の1本しか入らない**（4本ぶん課金される）。1タスク1本で頼み、`mergeAnimations` で1ファイルにまとめる
- **元絵の黒い輪郭線が、横や腕の面に縦のスジとして焼き込まれる**。対策は2段：
  1. 3D化の入力を「輪郭線だけ消した絵」にする（ChatGPT＝Codex の image_gen で作成。`generation.inputImage`。デザインの正は `front.png` のまま）
  2. 残った線は `line-cleanup.mjs` が正面を向いていない面の黒だけ埋める（無料・毎回自動）
- cheer は12秒ある。ゲームの演出に合わせて最長3〜4秒で切り上げる

## 元絵（Source of Truth）

1254px の原画はリポジトリにも手元にも無かった。代わりに、**ゲームの2Dリグそのものを関節0（原画どおりの立ち姿）でヘッドレスブラウザに描かせて**書き出した（`npm run character:export-source`）。
アトラスの大きいパーツから合成されるので、アトラス内の小さな全身図（約250px）より鮮明（618×764）。デザインは1画素も描き足していない。

→ `assets/characters/source/naru/front.png`（上書き禁止）／ 3D化の入力は派生物 `input.png`

腕が少し開いた立ち姿（A-pose寄り）なので、T-pose 画像の生成（有料・デザインが変わる危険あり）はまず挟まない。

## Tripo について分かったこと（公式ドキュメント 2026-09-29 確認）

- API は v2（`https://api.tripo3d.ai/v2/openapi`、`POST /task` に `type`）と v3（2026-04〜、機能ごとのエンドポイント）が並行運用。実装は仕様が安定していて SDK も使っている v2
- **Studio（Web）と API のクレジットは別会計**（共有されない）。1 credit = $0.01
- 失敗したタスクは課金されない（凍結 → 返金）。出力 URL は数分で切れるので成功したらすぐ落とす
- 人型で使えるプリセットが多い（idle / walk / jump / cheer / clap / dance_01〜06 / wave_goodbye / sit / sob / angry など101種）のは **rig v1.0 biped**。retarget できるのは `spec: tripo` だけ
- 1枚 → 4視点画像の生成が公式にある（10クレジット）。4視点 → モデルも可能
- 公式の注意：骨を入れた後にメッシュを加工（減面・パーツ分け等）すると骨が消える → 減面は生成時の `face_limit` と、骨を壊さないローカルの間引き（gltf-transform）だけでやる
- 三頭身キャラについての公式の記述は無し。「四肢がはっきり」「服は1枚」「アクセは少なめ」が推奨

## 手順

```sh
cp .env.example .env              # TRIPO_API_KEY=tsk_... を書く（コミットされない）
npm run character:build -- naru --provider tripo --dry-run   # 見積もりと残高だけ見る（使わない）
npm run character:build -- naru --provider tripo              # 生成（確認で y）→ 候補ができたら止まる
npm run character:review -- naru                              # 元絵と並べて、10項目を見て Approve / Reject
npm run character:build -- naru --provider tripo              # Approve 済みなら リグ → アニメ → 最適化 → 登録
npm run test:e2e
```

- Reject したら：`npm run character -- generate naru --provider tripo --new`（また30）
- 途中で落ちたら：同じコマンドをもう一度。**作ったタスクIDは保存してあるので、作り直さずに結果を取りに行く**
- 作成の返事を受け取る前に通信が切れたら：Tripo 側にタスクができているかもしれないので**自動では作り直さない**。
  https://platform.tripo3d.ai で確かめて、あれば `npm run character -- adopt naru --slot model --task <taskId>`、無ければ `--allow-recreate` を付けて再実行
- 新しいキャラ：`npm run character -- init <id> --source <正面画像> --name 表示名` → 上と同じ。ゲーム側は `index.json` と `character.json` を読むだけなのでコード変更は不要

## ゲーム側のしくみ

- `?r=3d` を付けて開いたときだけ3D。**覚えない**（次にふつうに開けば2D）。3Dのときは2DのWebGLを作らない（GPUを2つ持たない）

- `index.html` のゲームロジック（いつ何をするか）はそのまま。出来事が起きたら `3d/state-machine.js` に名前を渡すだけ
- 状態：ベース（ループ）= IDLE / WALK / RUN / SLEEP / SAD / DANCE、ワンショット = JUMP / HAPPY / EAT / LEVEL_UP / WAVE / PET / ANGRY
- 無いクリップは近いものに置き換える（RUN→WALK、EAT・LEVEL_UP・DANCE→HAPPY、SLEEP・SAD→IDLE）。クリップを足せば自動で使われる
- 切り替えは 0.25 秒のクロスフェード
- 読み込み失敗・WebGL が落ちた・平均 22fps 未満が5秒続いた → 自動で2Dに戻る
- 「動きを減らす」設定では3Dも静止で描く（この作業中に、2Dがこの設定でキャラを描かない既存バグを見つけて直した）

### 着せ替え・アクセ（今後）

- 服の色替え：Tripo の出力は1枚の焼き込みテクスチャ。今の2Dと同じ「シャツ・短パンの画素だけ HSL 変換」をテクスチャに掛ければ、モデルを作り直さずに（＝クレジットなしで）色が変わる
- アクセ（サングラス等）：`character.json` の `sockets.head.bone`（最適化時に頭の骨を自動検出）に別の小さな GLB を付ける。`R3.socket("head")` が取り付け点を返す
- 今は3Dモードではアクセを隠している（2D用の位置合わせのため）

## 2D（今）と 3D（Tripo）の比較

「3Dだから良い」とは決めない。数字が出ているものは実測、未計測のものはそう書く。

| 項目 | 2D メッシュリグ（今） | 3D（Tripo） |
|---|---|---|
| 元絵の再現度 | **原画そのもの**（100%） | AI の解釈が入る。顔（閉じ笑い目・猫口）の線が崩れる危険が最大のリスク。**Human Checkpoint で判断** |
| 表情 | **眉・目・口・ほっぺが独立して動く**（口パク・まばたきの代わり・しょんぼり等） | テクスチャに焼き込み。表情は変わらない（変えるには別の仕組みが要る） |
| 動きの自然さ | ばね＋式。関節11個なので動きの種類に限りがある | モーションキャプチャ由来のプリセット。体全体が動く。ただし三頭身だと腕が頭に埋まる等の破綻があり得る（要確認） |
| キャラらしさ | 手で調整したクセ（ポニテの揺れ・首の遅れ） | 汎用モーション。キャラ固有のクセは出にくい |
| 横・後ろ向き | できない | **できる** |
| ロード（配信量） | 画像 91KB（＋HTML に含む mesh 34KB） | three.js 167KB(gzip)＋モデル（Mock 86KB。本物は未計測、テクスチャ1024 WebP で 0.5〜1.5MB 程度の見込み） |
| FPS | 60fps（軽い） | 未計測（本物モデルで iPhone 実機計測が必要）。重ければ自動で2D |
| iPhone の発熱・電池 | 小 | 2Dより大きい。DPR 上限2・低電力指定・非表示時停止で抑えている |
| 制作時間（動きを1つ足す） | 数値を12個調整（人の手） | プリセット名を1行足す（10クレジット） |
| ランニングコスト | 0 | 1体 約95クレジット＋動き1つ10。表示には費用なし |
| 拡張性 | 新キャラは原画のメッシュ作り（mesh.py、今は手元に無い）から | **画像1枚＋コマンド**で新キャラ。設定ファイルだけでゲームに載る |

### 判断

- **既定は2Dのまま**にする。元絵の再現と表情は2Dの方がはっきり上で、このゲームの魅力はそこにある
- 3Dは「横を向く・歩き回る・動きの種類を増やす」場面で勝つ可能性がある。本物のモデルで次の3つを満たしたら、既定の切り替え（または部分採用）を検討する
  1. Human Checkpoint で「顔が変わっていない」と判断できる
  2. iPhone 実機で 50fps 以上・初回ロード 2MB 以下
  3. 三頭身でモーションが破綻しない（腕が頭を貫通しない等）
- 過去に「3Dレンダーの連番」をやめた経緯（実効 6〜11fps・805KB、コミット `e0d9401`）とは別物（今回はリアルタイム3D）だが、同じ轍を踏まないよう数字で判断する
